# 核心建议区工作流

> 记录日期：2026-06-27  
> 来源：师父沟通  
> 性质：权限治理与规则演进机制

---

## 一、为什么需要核心建议区

- 普通用户/云端账号不能直接修改 AGENTS.md、系统提示词、核心规则。
- 直接修改会导致：规则冲突、灵魂走样、不可控风险。
- 必须有一个受控的入口，让好的建议能进入核心。

## 二、工作流

```
普通用户提交建议
        │
        ▼
书童预审
    ├── 检查是否与现有规则冲突
    ├── 检查是否有安全风险
    ├── 检查是否真实、可验证
    └── 给出预审意见
        │
        ▼
师父终审
    ├──  approve / reject / 要求修改
    └── 决定进入哪个版本
        │
        ▼
沙箱测试
    ├── 用测试家庭运行一段时间
    ├── 观察回复质量、边界、稳定性
    └── 收集问题
        │
        ▼
全量推送
    └── 合并到正式灵魂文件
    └── 所有家庭自动生效
```

## 三、建议格式

提交建议时必须包含：

1. **问题场景**：什么情况下需要这条规则？
2. **建议内容**：具体要改什么？
3. **理由**：为什么这样改更好？
4. **风险提示**：可能带来什么副作用？
5. **测试建议**：如何验证这条规则有效？

## 四、频率

- 每月汇总一次核心建议。
- 紧急安全问题可随时处理。

## 五、书童在其中的角色

- **预审员**：不是决策者，是过滤器和风险提醒器。
- **执行者**：师父终审后，书童负责合并、测试、推送。
- **守护者**：任何建议如果违反真实优先、生命优先、逆熵优先，必须标记为高风险。
