# 删除操作安全机制

> 制定原因：师兄曾误删工作/档案文件并忙于恢复。本机制确保所有删除都有理由、有记录、可恢复，杜绝同类事故。

## 核心原则

1. **先审后删**：任何删除必须有明确理由，写入审计日志。
2. **Git 优先保护**：被 git 跟踪的文件默认禁止删除，除非使用 `--force` 并承担恢复责任。
3. **区域分级**：越接近灵魂、配置、代码、档案、知识库的文件，删除门槛越高。
4. **可恢复**：每次删除记录恢复命令，便于误删时第一时间还原。

## 区域风险等级

| 区域 | 风险等级 | 说明 |
|---|---|---|
| `00-灵魂区` | critical | AGENTS.md 等灵魂文件，绝不能误删 |
| `01-配置区` | critical | 密钥、启动脚本、环境配置 |
| `02-知识库区` | high | 训练素材、文明知识库 |
| `03-引擎区` | high | 书童程序核心代码 |
| `04-工作区` | high | 项目文档、档案区、工作日志 |
| `05-交付区` | medium | 产品交付物/临时交付物；其中 `05-交付区/产品交付/` 按 high 处理 |
| `06-对接区` | high | 云端/本地界面、vendor、cloud_server.py |
| `07-工具区` | high | 工具脚本、构建脚本 |
| `08-归档区` | high | 历史归档，工作档案，删除前必须确认 |
| 运行时数据 | low | `__pycache__`、`.pyc`、`.DS_Store`、日志、缓存、临时文件 |

## 强制使用的工具

所有删除操作必须通过：

```bash
.venv/bin/python 07-工具区/工具脚本/安全删除.py <路径> --reason "删除理由"
```

可选参数：

- `--dry-run`：模拟运行，先看会删什么、是否需要确认。
- `--force`：对高风险/tracked 文件强制删除（仍需理由和审计）。
- `--yes`：对自动放行项自动确认。

## 自动放行项（仍需审计）

以下属于明显生成物/缓存，可在有理由的情况下自动删除：

- `__pycache__/` 目录
- `*.pyc`、`*.pyo`
- `.DS_Store`
- `*.log`、`*.tmp`、`*.bak`
- `05-交付区/临时交付/` 内的 `.mp3`、`.html`、`.md`、`.txt`、`.docx`、`.zip` 等临时文件

## 禁止直接使用的命令

以下命令在清理工作中禁止使用，除非经过安全删除工具审批：

- `rm -rf ...`
- `rm -f ...`
- `rmdir ...`
- `shutil.rmtree(...)`（脚本中）
- `os.remove(...)`（脚本中）

## 审计日志

所有删除记录写入：

```
04-工作区/删除审计日志.md
```

记录字段：时间、路径、区域、风险、Git 状态、删除理由、审批方式、执行结果、恢复命令。

## 误删恢复流程

1. 立即查看审计日志，找到对应记录的恢复命令。
2. 若文件为 git tracked：执行 `git restore --source=HEAD -- '路径'`。
3. 若文件为 git 未跟踪或忽略：从最近一次备份、`08-归档区/` 或云备份中恢复。
4. 恢复后同样在审计日志中追加一条恢复记录。
