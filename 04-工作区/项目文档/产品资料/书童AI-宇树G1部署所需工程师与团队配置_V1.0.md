# 书童AI × 宇树G1 部署所需工程师与团队配置 V1.0

> **目标**：明确将书童AI系统部署到宇树G1机器人身上所需的人才、技能与团队配置  
> **适用对象**：项目负责人、技术负责人、HR、合作方  
> **更新日期**：2026-06-24

---

## 一、总体判断

将书童AI部署到宇树G1机器人身上，**不是单一工种能完成的工作**，需要**AI软件 + 机器人控制 + 系统集成 + 安全测试**的跨领域协作。

- **最低配置**：2 名核心工程师
- **推荐配置**：3-4 人小组
- **理想配置**：5-6 人完整团队（含产品与安全）

---

## 二、核心工程师（必备）

### 角色 1：AI / LLM 应用工程师

**人数**：1 人

**必须掌握的技能**：

| 技能 | 深度 | 说明 |
|------|------|------|
| Python | 精通 | 书童系统主要开发语言 |
| 大模型应用开发 | 熟练 | 熟悉 Ollama、API 调用、Prompt Engineering |
| 语音识别/合成 | 了解 | 了解 Whisper、edge_tTS 或类似工具 |
| 本地模型部署 | 熟练 | 能在 Mac/Linux 上部署和调试 DeepSeek-R1 等模型 |
| 多模态交互 | 了解 | 语音、文本、摄像头数据的融合处理 |
| 系统集成 | 熟练 | 能把语音、大模型、机器人控制串成完整链路 |

**主要职责**：
1. 部署和维护书童AI大脑系统
2. 调试 DeepSeek-R1:32b 在书童场景下的表现
3. 实现"语音指令 -> 书童理解 -> 机器人动作"的决策链路
4. 优化回复速度、响应延迟
5. 处理书童系统的日常升级和故障

**面试考察点**：
- 是否实际跑通过 Ollama + 本地大模型？
- 是否做过语音对话系统？
- 是否理解 Prompt Engineering 和 RAG？
- 是否具备把多个开源工具串成产品的能力？

---

### 角色 2：机器人软件工程师

**人数**：1 人

**必须掌握的技能**：

| 技能 | 深度 | 说明 |
|------|------|------|
| ROS2 或 DDS | 精通其一 | 宇树G1使用DDS通信，ROS2底层也是DDS |
| Python / C++ | 熟练 | 宇树SDK两种语言都有 |
| 机器人运动控制 | 了解 | 懂关节控制、步态、姿态等基本概念 |
| 网络通信 | 熟练 | 能让Mac与G1在同一局域网互通 |
| Linux / Ubuntu | 熟练 | 宇树SDK原生支持Ubuntu |
| Docker | 了解 | 当前方案用Docker运行宇树SDK桥接 |

**主要职责**：
1. 在 Mac 上搭建宇树G1的对接环境
2. 实现书童与G1的通信桥接（DDS/ROS2）
3. 封装G1基础动作：站立、坐下、前进、停止、挥手、转身
4. 读取G1传感器数据：姿态、IMU、电池、摄像头
5. 调试动作安全性、响应延迟、网络稳定性
6. 与宇树技术支持对接，解决固件/接口问题

**面试考察点**：
- 是否接触过宇树、波士顿动力、优必选等人形机器人？
- 是否做过 ROS2 / DDS 项目？
- 是否理解机器人正逆运动学？
- 是否有真实机器人调试经验？

**加分项**：
- 有宇树G1/H1/H2实际开发经验
- 参与过人形机器人比赛或项目
- 懂强化学习、模仿学习

---

## 三、辅助工程师（推荐配置）

### 角色 3：系统集成 / 测试工程师

**人数**：1 人

**技能要求**：
- 熟悉 Python 和 Linux
- 有软件测试经验
- 能写自动化测试脚本
- 懂网络抓包、日志分析
- 有耐心做重复性测试

**主要职责**：
1. 编写和执行系统集成测试用例
2. 测试每个语音指令对应的机器人动作
3. 记录延迟、稳定性、失败率
4. 模拟各种异常场景：网络断开、机器人摔倒、电量低、误识别
5. 输出测试报告和问题清单

---

### 角色 4：机器人硬件 / 嵌入式工程师

**人数**：0.5-1 人（可与角色2兼任，但最好独立）

**技能要求**：
- 懂电机、减速器、传感器
- 能处理机器人硬件故障
- 懂电源管理、散热
- 会看机器人状态指示灯、错误码

**主要职责**：
1. 处理G1硬件异常
2. 优化机器人续航和散热
3. 协助判断动作是否超出机械安全范围
4. 与宇树硬件团队沟通

**说明**：如果项目初期只跑基础动作，这个角色可以由机器人软件工程师兼任。但一旦涉及复杂动作或长期运行，建议有专职硬件工程师。

---

### 角色 5：网络安全 / 系统工程师

**人数**：0.5 人（可与角色1或角色3兼任）

**技能要求**：
- 懂网络配置、防火墙、VPN
- 了解 API 安全、认证机制
- 有 Mac / Linux 系统管理经验

**主要职责**：
1. 确保Mac与G1的通信安全
2. 配置桥接服务只对内网开放
3. 添加 API Key 认证
4. 防止机器人被未授权控制
5. 处理数据隐私和本地存储安全

---

## 四、非技术角色（重要但可选）

### 角色 6：儿童安全 / 产品专家

**人数**：1 人

**背景**：
- 教育学、儿童心理学、儿童发展学
- 或有丰富的儿童产品经验

**主要职责**：
1. 定义机器人在儿童身边的安全边界
2. 审核书童与孩子的交互话术
3. 设计安全测试场景
4. 确保产品符合儿童保护伦理

**重要性**：
- 这是书童AI不能缺失的角色
- 技术团队容易只关注功能实现，忽视儿童心理和伦理风险
- 建议至少有一名顾问级专家

---

### 角色 7：项目经理 / 技术负责人

**人数**：1 人

**职责**：
1. 协调AI、机器人、测试、安全各方
2. 与宇树商务和技术对接
3. 把控项目进度和风险
4. 向师父/决策层汇报

---

## 五、团队配置方案对比

| 配置 | 人数 | 角色 | 适用阶段 | 风险 |
|------|------|------|---------|------|
| **最低配置** | 2人 | AI工程师 + 机器人工程师 | 概念验证/POC | 无人专门做测试和安全，风险较高 |
| **推荐配置** | 3-4人 | AI + 机器人 + 测试 + （安全/产品兼职） | 小范围试点 | 能基本覆盖技术栈，儿童安全需外部顾问 |
| **理想配置** | 5-6人 | AI + 机器人 + 硬件 + 测试 + 网络安全 + 产品/安全 | 正式产品化 | 各环节都有专人，风险最低 |

## 八、招聘建议

### 优先招聘顺序

1. **第一位：机器人软件工程师**  
   这是最大瓶颈，懂宇树/ROS2/DDS 的人比 AI 工程师稀缺。

2. **第二位：AI / LLM 应用工程师**  
   负责把书童系统跑通，与机器人工程师对接。

3. **第三位：测试/安全工程师**  
   产品上线前必须有专人做安全测试。

### 人才来源

- 宇树生态开发者社区
- ROS/ROS2 开发者社区
- 人形机器人公司（优必选、智元、傅利叶等）
- 自动驾驶公司（很多工程师懂 DDS 和传感器融合）
- AI 应用创业公司

---

## 九、对外沟通话术

当有人问"部署书童AI到机器人上要什么人"时，可以这样说：

> "需要两类核心人才：一类是懂本地大模型和语音交互的 AI 应用工程师，负责书童的大脑；另一类是懂 ROS2/DDS 和宇树机器人的机器人软件工程师，负责机器人的身体控制。最低 2 人可以做技术验证，但要产品化至少需要 3-4 人，加上儿童安全专家。"
