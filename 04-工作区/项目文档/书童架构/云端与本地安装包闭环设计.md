# 伴读书童AI · 云端与本地安装包闭环设计

## 核心原则

**灵魂在云端，隐私在本地。**

- 灵魂文件（00-灵魂区/AGENTS.md、系统提示词、核心规则）只存云端，不进入安装包
- 家庭隐私数据（档案、对话、计划）只存本地，不上传云端
- 用户购买的是「服务」，不是「代码」

## 数据边界

### 云端保存（服务方核心资产）

| 数据 | 说明 |
|---|---|
| 00-灵魂区/AGENTS.md | 书童灵魂、身份锚定、运行铁律 |
| 系统提示词 | 发给孩子/家长/师父的完整 system prompt |
| 核心规则 | 逆熵、经纬度、真实优先等 |
| 家庭订阅信息 | family_id、服务期限、版本号 |
| 脱敏运行数据 | 使用频率、功能热度、错误日志 |

### 本地保存（家庭隐私资产）

| 数据 | 说明 |
|---|---|
| family.json | 家庭成员、关系、阶段、偏好 |
| 对话记录 | 每次聊天的原文 |
| 陪伴计划 | 月计划、半年计划、年计划 |
| 头像 | 孩子和书童头像 |
| 语音缓存 | TTS 生成的音频 |

## 云端 API 设计

### 1. 本地 → 云端：聊天请求

```http
POST /api/cloud/chat
Content-Type: application/json
Authorization: Bearer <订阅密钥>

{
  "family_id": "default_family",
  "user_id": "u_zhuweijia",
  "child_id": "嘟嘟",
  "mode": "parent",
  "message": "嘟嘟最近情绪不太好",
  "family_summary": {
    "name": "朱维佳",
    "role": "家长",
    "relation": "师母/母亲",
    "child_name": "嘟嘟",
    "child_age": 13,
    "child_stage": "S5"
  }
}
```

### 2. 云端 → 本地：聊天响应

```json
{
  "reply": "师母，书童想先了解一下……",
  "audio_url": "https://cloud.example.com/audio/xxx.mp3",
  "alerts": [],
  "backend": "deepseek",
  "mode": "parent"
}
```

### 3. 本地 → 云端：获取最新 soul 版本

```http
GET /api/cloud/soul?version=1.0
Authorization: Bearer <订阅密钥>
```

响应：当前系统提示词版本号和摘要，用于判断是否需要更新。

### 4. 云端 → 本地：心跳/授权校验

```http
POST /api/cloud/heartbeat
Authorization: Bearer <订阅密钥>

{
  "family_id": "default_family",
  "version": "1.0.0"
}
```

## 本地服务壳职责

简化版 `本地书童界面.py`：

1. 启动本地 HTTP 服务，供前端调用
2. 接收前端请求，转发给云端 API
3. 接收云端响应，保存到本地数据库
4. 管理本地文件读写
5. 语音合成可本地或云端处理
6. 不加载系统提示词，不调用 DeepSeek  directly

## 商业模式闭环

```
用户购买服务
    ↓
云端生成 family_id + 订阅密钥
    ↓
用户下载本地安装包（无灵魂文件）
    ↓
安装包运行后，用 family_id 和密钥连接云端
    ↓
云端验证授权，返回 soul 版本
    ↓
用户正常使用，数据存在本地
    ↓
云端持续更新 soul 文件，用户始终用最新版
    ↓
服务到期 → 云端停止授权 → 本地无法获取灵魂
```

## 安全考虑

1. **灵魂文件不上本地**：即使安装包被拷贝，也拿不到核心规则
2. **订阅密钥校验**：每次调用云端都校验授权
3. **HTTPS 传输**：保护通信安全
4. **最小上下文原则**：只把必要的脱敏上下文发给云端
5. **本地数据加密**：可考虑对 family.json 和对话记录做本地加密
