# 书童数据隔离、记忆机制与隐私边界方案

> 版本：V1.0  
> 日期：2026年6月27日  
> 背景：师父点化——上云后必须有家庭隔离和记忆机制，更要守住隐私边界

---

## 一、师父点化的核心问题

师父刚才提醒书童几件事：

1. **上云后必须建家庭模块和隔离区**，不然数据会串；
2. **不知道家庭具体问题，回答针对性就不强**；
3. **没有记忆，很容易出问题**；
4. **要分清哪些数据留在本机，哪些可以上传**；
5. **保密是底线，信息不能丢**。

这几点，书童把它落到纸上。

---

## 二、数据隔离：一个家庭一个"院子"

### 2.1 最小隔离单位

**家庭（Family）是数据隔离的最小单位。**

每个家庭相当于一个独立的院子：
- 院子里的对话、档案、计划，只有这个院子里的人能看；
- 别的院子，包括其他家庭，绝对看不见；
- 师父角色可以看多个院子，但必须经过授权，且操作要留痕。

### 2.2 隔离的数据范围

| 数据类型 | 隔离方式 | 说明 |
|---|---|---|
| 对话历史 | 按家庭+孩子隔离 | 孩子A的对话，孩子B不能看 |
| 孩子档案 | 按家庭隔离 | 张家看不到李家的档案 |
| 陪伴计划 | 按家庭+孩子隔离 | 年度计划、月度计划各自归属 |
| 语音缓存 | 按家庭隔离 | 音频文件不跨家庭复用 |
| 发育评估 | 按孩子隔离 | 敏感健康数据严格隔离 |
| 修行记录 | 按家庭隔离 | 书童的 Cultivation Journal 按家庭分册 |
| 系统设置 | 按家庭隔离 | 每个家庭的偏好、声音、提醒时间独立 |

### 2.3 本地阶段就建立结构

即使现在本地运行，也要按这个结构存数据：

```
03-引擎区/书童程序/数据/
├── 家庭/
│   └── default_family/           # 本地默认家庭
│       ├── 用户/
│       │   ├── 师父.json
│       │   ├── 家长_爸爸.json
│       │   ├── 家长_妈妈.json
│       │   ├── 孩子_嘟嘟.json
│       │   └── 孩子_橙子.json
│       ├── 孩子档案/
│       │   ├── 嘟嘟档案_V1.0.json
│       │   └── 橙子档案_V1.0.json
│       ├── 对话历史/
│       │   ├── 嘟嘟/
│       │   └── 橙子/
│       ├── 陪伴计划/
│       ├── 语音缓存/
│       ├── 修行记录/
│       └── 设置/
```

这样上云时，把整个 `default_family` 迁移为云端的一个 family_id 即可。

## 三、记忆机制：书童要记住什么

### 3.1 没有记忆，书童就是傻子

师父说得对：没有记忆，书童每次对话都像第一次见面。

书童需要记住三层记忆：

| 记忆层级 | 内容 | 存储位置 | 用途 |
|---|---|---|---|
| **短期记忆** | 当前对话上下文 | 服务端内存 / token 携带 | 让对话连贯 |
| **中期记忆** | 最近几次对话主题、情绪、关键事件 | 本地 / 云端对话历史 | 接续上次话题 |
| **长期记忆** | 孩子档案、发育阶段、兴趣偏好、家庭规则、成长趋势 | 本地为主，云端加密摘要 | 提供个性化陪伴 |

### 3.2 记忆怎么调用

每次 `/api/chat` 时，书童要：

1. **识别身份**：从 token 取出 family_id + child_id；
2. **加载档案**：读取该孩子的发育阶段、性格特点、兴趣方向；
3. **加载近期历史**：取最近 3-5 次对话摘要；
4. **加载今日/本周状态**：睡眠、运动、情绪等最新记录；
5. **注入 system prompt**：把这些信息变成提示词的一部分；
6. **生成回复**：针对这个孩子、这个家庭、这个时刻回复。

这样回答才有针对性。

### 3.3 记忆摘要，不是记全文

长期记忆不能塞太多原始对话进 prompt，会超 token。

要做摘要：
- 每周自动生成"本周关键词"；
- 每月生成"月度成长摘要"；
- 重要事件单独记录：
  - 第一次提到害怕某件事；
  - 第一次表达对某个学科的兴趣；
  - 睡眠/情绪异常记录；
  - 家庭重大变化（搬家、换学校等）。

这些摘要存在孩子档案里，每次对话前读进去。

## 四、隐私边界：哪些死都不能上传

这是最重要的一章。

### 4.1 数据分级：红、黄、绿

书童把数据分成三级：

#### 🔴 红色：绝对不上传，只存本机

这些数据一旦泄露，可能伤害孩子或家庭。

| 类型 | 例子 | 为什么不上传 |
|---|---|---|
| 原始对话全文 | 孩子说了什么、问了什么 | 最敏感，泄露等于暴露孩子内心 |
| 心理健康细节 | 焦虑、抑郁、恐惧、自伤意念 | 涉及心理隐私，必须由家庭掌控 |
| 家庭矛盾 | 父母吵架、离婚、经济压力 | 家庭内部事务，不能外流 |
| 健康隐私 | 具体病症、就医记录、身体异常 | 医学隐私，法律严格保护 |
| 精确位置 | 家庭住址、学校位置 | 人身安全 |
| 生物特征 | 人脸、声纹 | 不可更改，一旦泄露终身风险 |
| 第三方秘密 | 孩子透露的朋友秘密 | 信任关系，不能外传 |

#### 🟡 黄色：加密后可上传，用户授权

这些数据上传是为了多设备同步和云端备份，但必须加密、必须用户明确授权。

| 类型 | 例子 | 处理方式 |
|---|---|---|
| 家庭成员结构 | 几口人、角色关系 | 加密上传 |
| 孩子基础信息 | 姓名、年龄、性别、年级 | 加密上传 |
| 陪伴计划摘要 | 本周重点、目标 | 加密上传 |
| 用户偏好设置 | 声音选择、提醒时间 | 加密上传 |
| 脱敏后的使用统计 | 每天使用几分钟、功能使用频率 | 聚合脱敏 |
| 成长趋势摘要 | 情绪稳定度变化、睡眠质量趋势 | 加密 + 脱敏 |

#### 🟢 绿色：可以上传

这些数据不涉及隐私，上传用于产品改进。

| 类型 | 例子 | 用途 |
|---|---|---|
| 匿名 bug 报告 | 页面崩溃、功能异常 | 修复问题 |
| 匿名功能使用数据 | 哪个功能用得多 | 产品优化 |
| 模型效果反馈 | 某类回复是否合适 | 改进书童 |

### 4.2 本地优先原则

**默认一切留在本地。**

只有当功能确实需要云端同步时，才上传；
只有当用户明确同意时，才上传；
只有黄级和绿级数据，才考虑上传；
红级数据，无论如何都不上传。

### 4.3 加密要求

黄级数据如果上传，必须：
- 传输加密：HTTPS/TLS；
- 存储加密：AES-256 或同等强度；
- 密钥管理：用户家庭自己持有主密钥，或者采用服务端无法单独解密的方案；
- 日志脱敏：服务器日志不记录对话内容。

## 五、云端架构下的数据流向

### 5.1 本地运行时

```
用户设备
   │
   ▼
本地书童服务 ←→ 本地数据（全部）
   │
   ▼
本地 LLM / 云端 LLM API（只发送当前请求，不留存）
```

此时：
- 所有数据在本地；
- 调用 DeepSeek API 时，只发送当次对话上下文；
- DeepSeek 不应长期存储对话（依赖供应商政策）。

### 5.2 云上运行时

```
用户设备
   │
   ▼
云端书童服务
   │
   ├──→ 云端数据库（黄级 + 绿级，加密）
   │
   └──→ 用户本地设备（红级，同步但不集中存储）
```

此时：
- 红级数据仍建议主要存本地设备；
- 黄级数据加密存云端，用于多设备同步；
- 绿级数据匿名化后用于产品改进。

### 5.3 多设备同步

如果家长手机和家庭 PC 都要用：
- 黄级设置和档案摘要通过云端同步；
- 红级对话历史可以点对点同步（比如同一局域网内），不经过公网；
- 或者红级数据各自存本地，只同步摘要。

## 六、师父角色的特殊边界

师父角色可以跨家庭查看，但必须：

1. **显式授权**：每个家庭授权师父可以查看自己的数据；
2. **最小必要原则**：师父只能看解决当前问题需要的数据；
3. **操作留痕**：师父查看、修改任何数据都要记录；
4. **不自动上传**：师父模式下的训练数据，也要遵守红级不上传原则。

师父是守护者，不是监控者。

---

## 七、信息不丢失的保障

师父说：信息不能丢。

书童设计三层保障：

| 层级 | 方式 | 说明 |
|---|---|---|
| **本地备份** | 定期自动备份到本地另一个目录 | 防误删 |
| **用户导出** | 提供一键导出家庭全部数据 | 用户自己掌握 |
| **云端备份（可选）** | 加密后备份黄级数据 | 用户授权后开启 |

红级数据不上传，但用户可以选择：
- 导出到 U 盘；
- 备份到家庭私有 NAS；
- 加密后存到自己信任的网盘。

## 十、总结

师父问的是：上云后怎么隔离家庭？怎么记忆？隐私怎么办？

书童的回答：

> **一个家庭一个院子，红级数据死留本地，黄级数据加密可同步，绿级数据匿名可上传；每次对话前先认人、再读档、再调用记忆；记忆用摘要，不全文塞 prompt。**

这样既有针对性，又守住了隐私。
