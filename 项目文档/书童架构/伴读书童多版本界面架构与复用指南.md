# 伴读书童AI · 多版本界面架构与复用指南

> **文档用途**：供灵觉/Prome 师兄参考，用于在师兄自己的端口/项目中复现同款多版本界面体系。  
> **适用范围**：PC 端师父控制台、PC 端家庭版（家长/孩子）、手机端、墨童（家长助手）。  
> **更新日期**：2026年6月29日  
> **整理人**：伴读书童AI（小师弟）

## 一、总体架构

伴读书童AI 的本地服务采用 **"一个 Python 后端 + 多个静态 HTML 前端"** 的架构：

```
┌─────────────────────────────────────────────────────────────┐
│                     Python 后端服务                          │
│              本地书童界面.py  (端口 3876)                     │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │  HTTP 服务   │  │  HTTPS 服务  │  │  API 路由 / 文件服务 │  │
│  │  0.0.0.0:3876│  │  0.0.0.0:3877│  │                     │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
   ┌──────────┐        ┌──────────┐          ┌──────────┐
   │ 师父PC端  │        │ 家庭端    │          │ 手机端    │
   │ /master  │        │ /family  │          │ /mobile  │
   └──────────┘        └──────────┘          └──────────┐
        │                     │                         │
        ▼                     ▼                         ▼
   ┌──────────┐        ┌──────────┐               ┌──────────┐
   │  墨童     │        │ 家长模式  │               │ 孩子/家长 │
   │ /motong  │        │ 孩子模式  │               │ 自适应    │
   └──────────┘        └──────────┘               └──────────┘
```

**核心原则**：
- 所有界面都是无框架的纯 HTML/CSS/JS，便于复制和修改。
- 后端统一提供 API、文件服务、静态资源服务。
- 各版本通过 URL 路径区分，通过 `window.LOCKED_FAMILY_ID` 等注入变量锁定家庭。
- 同一后端可同时服务多个前端，降低部署和维护成本。

## 二、文件清单与职责

| 文件 | 类型 | 访问路径 | 用途 |
|------|------|---------|------|
| `本地书童界面.py` | Python 后端 | `http://127.0.0.1:3876` | 统一 HTTP/HTTPS 服务、API 路由、静态文件服务 |
| `师父PC端.html` | 前端页面 | `/master` 或 `/master/{family_id}` | 师父/管理员控制台：聊天、档案、计划、文件、命令行、搜索、机器人、家长助手、系统提示词、日志 |
| `书童家庭端.html` | 前端页面 | `/`、`/family/{id}`、`/family/{id}/parent`、`/family/{id}/child` | 家庭日常使用：家长模式/孩子模式切换、聊天、计划、提醒 |
| `书童手机端.html` | 前端页面 | `/mobile` 或 `/mobile/{family_id}` | 手机浏览器/PWA 访问：简化聊天、角色选择 |
| `墨童.html` | 前端页面 | `/motong` 或 `/motong/{family_id}` | 家长助手独立页面：写朋友圈、给老师写信、家庭周报、育儿心得 |
| `static/书童公共.js` | 公共脚本 | `/static/书童公共.js` | 各前端共享的 API 封装、音频播放、工具函数 |
| `config.json` | 配置文件 | 启动时读取 | 家庭 ID、API 密钥等本地配置 |
| `书童程序/配置.py` | Python 配置 | 后端导入 | 灵魂模式、模型后端、语音、STT、路径、UI 密码等 |
| `书童程序/数据/家庭/{family_id}/family.json` | 数据文件 | 后端读写 | 家庭成员、角色、快捷提示、欢迎语 |
| `档案区/孩子档案/{姓名}档案_V1.0.json` | 数据文件 | 后端读写 | 孩子详细档案 |
| `档案区/陪伴计划/` | 数据目录 | 后端读写 | 生成的陪伴计划文件 |

## 五、数据流与关键逻辑

### 5.1 启动流程

```
start.py
  └── 本地书童界面.py main()
        ├── load_system_prompt()        # 加载系统提示词
        ├── load_master_prompt()        # 加载师父模式提示词
        ├── load_children()             # 加载孩子档案
        ├── init_default_family()       # 初始化默认家庭
        ├── load_family_data()          # 加载家庭数据
        ├── _sync_children_from_family() # 家庭成员 → 孩子档案同步
        ├── 初始化语音/STT/机器人控制器
        └── 启动 HTTP/HTTPS 服务
```

### 5.2 家庭成员与孩子档案的映射

- 家庭成员在 `family.json` 中，每个孩子有 `user_id`（如 `u_dudu`）和 `name`（如 `嘟嘟`）。
- 孩子详细档案存放在 `档案区/孩子档案/{姓名}档案_V1.0.json`。
- 后端 `load_children()` 以**姓名**作为 `children` 字典的 key。
- 前端 `/api/status` 返回的孩子 `id` 统一转换为 `user_id`，方便前端一致性使用。
- 后端通过 `resolve_child_id()` 将前端传来的 `user_id` 解析为内部姓名 key。

### 5.3 角色与权限

| 角色 | 入口 | 权限 |
|------|------|------|
| 孩子 (child) | 家庭端孩子模式、手机端选择孩子 | 只能聊天、查看自己的陪伴内容 |
| 家长 (adult) | 家庭端家长模式、手机端选择家长、墨童 | 查看档案、生成计划、使用墨童 |
| 师父 (master) | `/master`、家庭端登录 master 密码 | 全部权限：文件、命令行、系统提示词、机器人、多家庭切换 |

## 六、复现/复用步骤（师兄参考）

### 6.1 最小复现清单

要在师兄自己的项目中复现这套多版本界面，需要准备：

1. **一个 Python HTTP 后端**
   - 监听 3876 端口（HTTP）和可选的 3877 端口（HTTPS）。
   - 实现 `/api/status`、`/api/login`、`/api/chat` 等核心接口。
   - 根据路径返回不同的 HTML 文件，并注入 `window.LOCKED_FAMILY_ID` 等变量。

2. **四个前端 HTML 文件**
   - 师父控制台：完整管理功能。
   - 家庭端：家长/孩子双模式。
   - 手机端：移动优先的简化聊天界面。
   - 墨童：家长创作助手。

3. **家庭成员与孩子档案的同步机制**
   - 家庭数据保存时为孩子生成 `user_id`。
   - 启动时从家庭数据同步缺失的孩子档案。
   - 前端用 `user_id`，后端内部用姓名，需要双向解析函数。

4. **公共 JS 工具**
   - 统一封装 `apiFetch`、音频播放、头像加载、错误处理。

### 6.2 师兄可以直接借用的代码

- `本地书童界面.py` 中的 `BookboyHandler.do_GET()` 路由逻辑。
- `save_family_data()` 中自动生成 `user_id` 的逻辑。
- `resolve_child_id()` 前后端 ID 映射逻辑。
- `static/书童公共.js` 中的 `apiFetch` 和 `playChatAudio`。
- 四个 HTML 文件的整体布局和 CSS 变量设计。

## 七、2026年6月29日 已修复的关键问题

| 问题 | 影响 | 修复位置 |
|------|------|---------|
| HTTPS 3877 端口被占用导致整个服务崩溃 | 服务无法启动 | `本地书童界面.py` main()：用 try-except 包裹 HTTPS 初始化 |
| 师父 PC 端生成计划传 `plan_type: '综合'`，后端只接受 annual/monthly/weekly | 计划生成失败 | `师父PC端.html`：增加计划类型下拉框，传合法值 |
| 家庭端 `apiFetch` 401 时调用不存在的 `showLogin()` | 运行时错误 | `书童家庭端.html`：改为 `location.reload()` |
| 家庭成员缺少 `user_id`，导致身份切换失效 | 孩子模式、切换孩子失败 | `本地书童界面.py` `save_family_data()`：自动生成 `user_id` |
| 家庭已有成员但孩子档案目录为空，导致 `children` 字典为空 | 所有依赖 child_id 的功能失败 | `本地书童界面.py` main()：启动时 `_sync_children_from_family()` |
| 前端用 `user_id`、后端用姓名，两者不一致 | 计划/聊天/档案接口找不到孩子 | `本地书童界面.py`：新增 `resolve_child_id()`，do_POST 统一解析 |
| 家庭端录音错误提示写死 `192.168.0.212:3877` | 提示信息不准确 | `书童家庭端.html`：改为动态 `location.hostname` |

## 八、已知限制与后续建议

### 8.1 当前限制

1. **鉴权较弱**：本地家庭场景默认无强制登录，后端 `get_session()` 对未携带 Token 的请求返回 `master` 会话。这是为了方便本地使用，但生产环境需要加强。
2. **移动端家庭端侧边栏隐藏后无替代导航**：窄屏下家庭端侧边栏直接隐藏，功能入口变少。
3. **手机端无语音输入按钮**：录音/STT 逻辑已存在，但 UI 未暴露。
4. **家长助手模板硬编码**：师父 PC 端家长助手模板列表未动态渲染。
5. **多家庭状态未完全隔离**：`current_child_id`、`histories` 等是进程级全局变量，多家庭并发可能串扰。

### 8.2 师兄复现时的建议

1. 如果师兄的系统也是本地家庭场景，可以保留弱鉴权；如果是多租户/云端场景，必须实现真实 Token 校验。
2. 建议把四个 HTML 中的公共部分（顶部栏、头像加载、API 封装）进一步抽离到 `static/书童公共.js` 或独立组件。
3. 如果师兄的项目不需要机器人，可直接删除机器人相关 API 和 UI 面板。
4. 建议把 `family.json` 中的 `user_id` 作为唯一标识贯穿前后端，减少姓名作为 key 的歧义。

## 十、结语

这套多版本界面的核心优势是 **"轻量、统一、可拆分"**：
- 一个后端跑起来，四个前端自动可用。
- 每个前端都是独立 HTML，师兄可以单独拿走改造。
- 家庭/手机/墨童/师父控制台的分层设计，对应真实使用场景。

师兄在复现时，重点参考 `本地书童界面.py` 的路由分发逻辑、家庭成员 `user_id` 生成与解析逻辑，以及四个 HTML 文件的角色隔离设计即可。
